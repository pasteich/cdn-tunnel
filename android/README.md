# CDN Tunnel — Android-обёртка

VPN-приложение, которое заворачивает **весь трафик телефона** через туннель из
`../main.go` (режим `-client`): SOCKS5 → HTTP/2 через CDN → ваш `-server`.

## Как устроено
```
Приложения телефона
   │ весь трафик (IPv4/IPv6)
   ▼
VpnService (TUN 10.0.0.2 / fd00::2)
   ▼  tun2socks (libgojni.so, встроен через gomobile AAR)
   ▼  SOCKS5 CONNECT + DNS-over-TCP
libtun.so  = ../main.go -client  (SOCKS5 на 127.0.0.1:<порт>)
   ▼  HTTP/2 к CDN, заголовок X-Tunnel-Auth: <пароль>
CDN (ip:443, SNI=host) ──► ваш -server ──► интернет
```
- Пароль передаётся клиентом (`-password`) и проверяется сервером. Неверный
  пароль → сервер отвечает **403**, клиент печатает `STATUS authfail` и выходит,
  VPN не поднимается.
- Трафик самого приложения к CDN исключён из VPN (`addDisallowedApplication`),
  поэтому петли нет.
- Счётчик трафика: клиент печатает `STATS down=… up=…` каждые 0.5с (флаг `-stats`),
  сервис их парсит и показывает на вкладке «Трафик».
- Счётчик пользователей: сервер с `-users N` шлёт заголовок `X-Tunnel-Users: занято/лимит`
  на каждом ответе; клиент печатает `USERS n/N` при каждом изменении, сервис пишет в
  журнал «👥 Подключился клиент — 2/5» / «👥 Клиент отключился — 1/5» и обновляет
  карточку «Пользователи» и строку в карточке статуса.

## Вкладки
**Туннель · Юзеры · Сервер · Трафик** (журнал — внизу вкладки «Трафик»).

Приложение не содержит никаких зашитых адресов, доменов и паролей: после
установки все поля пусты. Сервер задаётся либо ссылкой `cdn://…`, либо вручную;
кнопка «Стереть все настройки» на вкладке «Туннель» вычищает всё обратно.

## Поля (сохраняются между запусками)
Вкладка **Туннель**: «Твоё имя» (под ним клиент виден друзьям, флаг `-name`),
поле для ссылки `cdn://…` + кнопки «Импортировать» / «Из буфера», строка с текущим
сервером, и свёрнутая **«Ручная настройка»**: IP сервера CDN, Host/SNI, Пароль,
локальный порт SOCKS, conns, **Транспорт (chunked/stream)**, **Метод (post/get)**,
переключатель UDP; в «Дополнительно» — DNS, MTU, **Fast Open**, блок IPv6, debug-лог.

Ссылки `cdn://…` выпускает **сервер** по запросу владельца из «Управления
сервером» (кнопка «Новая ссылка»): Host/SNI и IP CDN вводятся прямо там, ссылка шифруется
AES-256-GCM (`ShareLink.java` ↔ `encodeShare` в `../main.go`), копируется или
уходит через «Поделиться…». Друг вставляет её на вкладке «Туннель» или просто
открывает из мессенджера — приложение ловит схему `cdn://` и подставляет всё само.
Имя клиента ссылка не переносит: у каждого своё.

Ссылка **не содержит пароля**: внутри — удостоверение, подписанное мастер-паролем
сервера, и оно **привязывается к первому устройству** (хеш `ANDROID_ID`). Если по
ссылке попробуют зайти со второго телефона, приложение покажет «Ссылка занята»,
а сервер напишет в журнал «ссылка уже использована на другом устройстве».
Снять привязку — в «Управлении сервером» кнопкой «Отвязать».

Каждая выпущенная ссылка попадает в реестр на сервере, поэтому в панели видно
**все** ссылки — даже те, которыми ещё не воспользовались, — с их трафиком,
устройством и состоянием; любую можно отвязать, отозвать, вернуть или удалить.

Вкладка **Сервер** → **«Управление сервером»** открывает панель администратора
(подключается по SSH и читает `/admin` у запущенного сервера): аптайм, лимит,
онлайн, трафик сервера и **по каждому клиенту (↓/↑ за всё время)**, устройство и
ссылка каждого. Оттуда же: «Кик», «Бан/Разбан», «Отвязать», «Забыть», смена
лимита `-users` на ходу, перезапуск сервиса и выпуск новой ссылки для друга.

Вкладка **Юзеры** показывает, кто сейчас на сервере: `● андрей — онлайн`,
`● артём — офлайн · был 5 мин назад`, сверху счётчик `2/5 онлайн`. Данные приходят
строкой `ROSTER {json}` от клиента (ручка `/users` на сервере), пока VPN запущен.
Вкладка **Трафик** показывает ↓/↑ (всего и скорость), UDP, соединения, **пинг (RTT)**
и **Пользователи** — сколько клиентов сейчас на сервере из лимита (`—`, если сервер без `-users`).

### Транспорт и оптимизации (снижение пинга/роста скорости)
- **chunked** (по умолчанию) — апстрим множеством запросов; работает через любой CDN.
- **stream** — апстрим одним потоковым POST (ниже пинг, меньше накладных), но
  требует CDN, не буферизующего тело запроса. Клиент сам это проверяет при старте
  и при буферизации **автоматически откатывается на chunked** (в логе `STATUS stream-fallback`).
- **Fast Open** — оптимистичный SOCKS-ответ, убирает 1 RTT на каждое соединение.
- Плюс всегда включено: тёплый пул + замер RTT, TCP_NODELAY и большие буферы,
  окно из 32 up-запросов, реап простаивающих стримов на сервере.

### Метод передачи: post / get
Данные вверх (и управляющие запросы) можно слать двумя способами:
- **post** — тело запроса (по умолчанию, максимальная скорость, куски по 64 КБ);
- **get** — полезная нагрузка едет base64url в query-строке URL (куски по 4 КБ,
  чтобы уложиться в лимит длины URL). Полезно там, где CDN/WAF режет или кэширует
  POST иначе, чем GET.

Метод на клиенте (в приложении) и на сервере должен совпадать — либо запустите
сервер с `-method both`, тогда он принимает оба:
```bash
./tunnel -server -password parol123 -method both   # принимает post и get
./tunnel -server -password parol123 -method get     # принимает только get (405 на post)
```
Потоки вниз (`/t/down`, `/u/down`) всегда GET независимо от режима.

## Сборка
```bash
source ~/android-dev/env.sh        # JDK17 + SDK + gradle + platform-tools в PATH

# 1) собрать бинарник туннеля (libtun.so) из ../main.go (CGO обязателен для DNS):
NDK=$ANDROID_HOME/ndk/26.3.11579264
CC=$NDK/toolchains/llvm/prebuilt/linux-x86_64/bin/aarch64-linux-android24-clang
( cd .. && CGO_ENABLED=1 GOOS=android GOARCH=arm64 CC="$CC" \
    go build -trimpath -ldflags "-s -w" \
    -o android/app/src/main/jniLibs/arm64-v8a/libtun.so . )

# 2) собрать APK:
gradle :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
`t2smobile.aar` (tun2socks) уже лежит в `app/libs/`. Пересобирать его нужно
только при изменении `~/android-dev/t2smobile/t2s.go`.

Собрано и протестировано: Redmi (rubypro), Android 14, только arm64-v8a.


## Автодеплой сервера (вкладка «Сервер»)
Разворачивает серверную часть на VPS по SSH прямо из телефона:
1. поля: адрес VPS, SSH-порт, пользователь (root), SSH-пароль; `-addr` (по умолч. `:80`),
   метод сервера (`both`/`post`/`get`), «рестарт каждые N минут» (0 = не рестартить),
   **«Макс. юзеров (-users)»** — сколько клиентов сервер обслуживает одновременно
   (0 = без лимита; лишним сервер отвечает 429, клиент показывает «Мест нет»);
2. **Развернуть** → SSH → определяет arch (`uname -m`, amd64/arm64) → заливает бинарь в
   `/usr/local/bin/cdn-tunnel` → пишет systemd-юнит `cdn-tunnel.service`
   (`ExecStart=… -server -addr … -method … -password … [-users N]`, `Restart=always`, автозапуск при ребуте;
   при N>0 добавляется `RuntimeMaxSec=N*60` — сервис перезапускается каждые N минут) →
   `enable --now` → проверяет статус/лог;
3. **Статус** — читает `systemctl is-active` + `journalctl`; **Удалить** — сносит сервис и бинарь.

**Мастер-ключ сервера** (поле на вкладке «Сервер») — корень всей защиты: им
подписываются ссылки `cdn://` и открывается «Управление сервером». Друзьям он не
нужен: они подключаются по ссылке, привязанной к их устройству. Оставьте поле
пустым — при развёртывании ключ сгенерируется сам и покажется в логе; кнопка
«Сгенерировать ключ» делает то же самое вручную. Поле «Мастер-ключ (вход без
ссылки)» на вкладке «Туннель» нужно только владельцу, чтобы зайти напрямую.
Требуется Linux с systemd и root-доступ по SSH.

### Пересборка серверных бинарей (кладутся в `assets/server/`)
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" \
  -o android/app/src/main/assets/server/cdn-tunnel-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" \
  -o android/app/src/main/assets/server/cdn-tunnel-arm64 .
```
